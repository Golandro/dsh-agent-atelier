# 0007 — 工作空间范围是软边界：非法 cwd 回退用户全局

票 37 grilling 裁决（2026-11-05，Q10–Q13）：面板的读写范围由选中的 DSH Workspace 决定，但 cwd 对服务端只是**发现起点，不是身份**。三条一反直觉的决定：

- **非法/缺失 cwd 不是错误**：空串、非绝对路径、目录不存在一律按「显式无项目层」处理，回退**用户全局**（只扫用户级与随包），不再返回 400。坏输入给可用答案，不把面板打瘫。
- **服务端不再隐式猜宿主 cwd**：删掉各路由的 `cwd ?? process.cwd()`。客户端没传 cwd 也走用户全局——宿主进程目录不再是默认范围。
- **「缺省」与「显式无项目层」在控制面分开**：registry 层早已支持（`cwd === undefined` → 不解析项目根），是控制面把 `undefined` 吃成宿主默认。修复落在控制面，不下沉到 registry；state 响应回带真正解析出的 `projectRoot`（可空），UI 才能诚实显示「已回退」以及「所选目录 → 实际项目根」。

## Considered Options

- **严格校验（坏 cwd 一律 400）**：客户端会话里工作空间目录被删/移走，整块面板就报错；否决——面板是全局工具，应降级而不是瘫掉。
- **隐式宿主 cwd 兜底**（`cwd ?? process.cwd()`）：服务端替用户选范围，且「用户全局」这个状态永远不可达；否决。
- **客户端补 realpath 归一后再比对**：realpath 只有宿主知道；否决——命中失败即落用户全局，不猜。

## Consequences

- wire 有一处向后不兼容的**语义**变更：坏 cwd 从 400 变 200 + 用户级数据；state 响应多一个可空 `projectRoot`。票 37 同步更新 `src/dsh/host/wire.ts` 的冻结注释与用例。
- 「用户全局」有三种用户含义（主动选择 / 所选工作空间失效回退 / 列表不可用），UI 必须分开展示，不能都写「用户全局」。
- 「在未注册目录里看项目层」的旧能力有意放弃——那正是「服务端猜 cwd」。需要项目层，就把目录注册成 Workspace。
