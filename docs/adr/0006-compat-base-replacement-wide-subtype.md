# 0006 — 组装注册双模：兼容层是基础包，替换模式是额外包

票 04 grilling 裁决（2026-10-24，Q14–Q16）：prompt 组装的运行时注册**不打上游补丁**（上游补丁不可行，最多经 `cordis.patch.yml` 改掉插件行），双模交付：

- **兼容层是基础包**：scoped 扩展注册进原版 `ctx.systemPrompt`——同名 scoped 填空 `deployment:persona-prefix`（order 0，复用原生遮蔽语义）、自有节 `atelier:model-sys`（order −500）、`section()` disposer 支撑**全量异步重载**。是产品面，**兼容优先**。
- **替换模式是额外包**：patch／替换原版实现，功能更多，**暂不实现**（票 04 只落缝形状与基础接口）；激活面是 `cordis.patch.yml` 插件行改换，不是上游 PR。
- **替换模式接口是基础模式接口的宽子类型**：基础成员全保留、只增不改（宽度扩展）；下游按基础接口编码，两模通吃。patch 模式返回的值更丰富，但接口收敛在基础面——此前「两接口不强求统一」的读法以此为准修正。
- **无能力探测**：下游服务初始化完毕后调兼容模式包提供的 API（基础面）。HMR：服务端与客户端**各自不同的回调信号**，由 cordis 提供、**析构 effect 发出**（注册 sink 的 disposer 即重载信号发出点）。

## 不变式（门）

- **只增不改**：替换模式不得改变基础成员的语义与返回契约；「更丰富」只能发生在新增成员或基础返回值的扩展字段上。两模行为一致性（同输入同输出的节序／断点／lint）进测试面锁死。
- **同一注册面只有一份实现**：替换包经 `cordis.patch.yml` 激活时兼容层让位（对齐 core-design「同一个服务只 provide 一次」）。
- 无能力探测的前提是「下游只依赖基础面」；任何未来让下游分叉行为的需求必须走宽子类型的新增成员，不得给基础成员加条件语义。

## Considered Options

- **上游补丁／PR 进 DSH 原版**：维护者裁决不可行（「不可能做上游补丁的」）；否决。
- **vendored fork 长期维护**：永久分叉成本；否决。
- **bundle 内 runtime 补丁＋宽子类型接口（选定）**：兼容层基础包先交付，替换模式额外包经 `cordis.patch.yml` 激活；接口收敛在基础面、宽子类型扩展。
- **统一抽象缝＋双适配器等价＋启动期能力探测**（grilling 初荐）：被否——无探测、patch 返回更丰富、接口是宽子类型而非平行适配器。

## Consequences

- 票 04 交付：规划器（纯函数）＋兼容层注册 sink（全量异步重载）＋基础接口形状；替换模式适配器空缺，等额外包票收。
- 基础接口 = 跨包契约面；07 的 agent→plan 关联簿、06 的 lint 消费都按基础接口编码。
- HMR 回调信号挂在注册 sink 的 disposer（析构 effect）；服务端与客户端信号各自独立。
- `cordis.patch.yml` 是替换模式的唯一激活面，替换包票动工前核对插件行改换与回滚（`docs/agents/harness-facts.md`）。
- **激活机制核查（2026-10-24）**：宿主 patch 按 `id` 覆盖整行；`name` 是校验字段（不匹配即跳过），不能就地改名；被禁用的 required 行按「有意缺席」忽略 ⇒ 替换模式激活 = 停用兼容组装行并 `insert` 替换行，两行不得同时 provide 同一服务。
