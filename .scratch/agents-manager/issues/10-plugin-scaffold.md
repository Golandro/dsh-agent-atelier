**实现修正（均为实现期发现，与票面建议不同处）**

1. **注册点 key：`agents` → `agentRegistry`**。票面第 3 条与 Brief 建议的 `agents` 已被原生占用：`Service.listService({ service: "agents" })` 返回原生 Agent 注册表契约（`ctx.agents`：`currentInitiator` / `withInitiator` / `create` / `resume` / `register` / `list` / `roots` …）。故冻结为 `AGENT_REGISTRY_SERVICE = 'agentRegistry'`（现网目录中无此 key），并有单测断言它不得等于 `agents`。**这是本票最关键的实现期发现**：若照票面写 `ctx.provide('agents', …)`，将与原生服务撞名。
2. **包管理器用 npm 而非 pnpm**：本会话沙箱只允许写 workspace，pnpm 全局 store 在 workspace 之外 ⇒ 安装报 EROFS。改用 `npm install --cache <workspace>/.npm-cache`（`package-lock.json` 已入库），命令为 `npm test` / `npm run build` / `npm run typecheck`；内部仍是 vitest + tsc，与主仓一致。
3. **构建只用 tsc（无 bundler）**：`tsconfig.json` 只做 typecheck（`allowImportingTsExtensions` + `rewriteRelativeImportExtensions`，含 `test/`），`tsconfig.build.json` 只编 `src/` 并 emit 到 `lib/`；源码里的 `./registry.ts` 在产物中被改写为 `./registry.js`。package.json **不声明 `prepare`**，避免安装时触发 `pendingBuilds` 审批。
4. **读回限制（如实记录）**：Host `Service` 目录只收录「有声明契约」的类型化 service——原生 plain-object 注册（如 `webApp`）同样查不到，所以空壳 registry 无法按名读回。`Config` 条目里的 `status: absent` 表示该 row **未声明 Config**（现网 deck 的条目完全同形），不是「未挂载」。因此「通路活着」的证据是：loader entry 命中 + `application: applied` + 真实 Cordis 单测；若维护者要求 service 级读回，需给注册点补声明式契约（超出本票「零业务逻辑」范围，可作为后续小票）。**未声明 `Config` 的原因**：Config schema 需要 `z`（schema 库）作为**运行时**依赖，而本包以 symlink 方式装进 profile——Node 会从 workspace 真实路径解析依赖，缺依赖会直接把 row 装崩；脚手架因此刻意保持「运行时零依赖」。
