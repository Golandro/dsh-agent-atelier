## 范围

把「能在本 profile 里被安装、被 inspect、能跑单测」的最小插件骨架立起来，作为 01–07 的实现前置；**不含任何 01–07 的业务逻辑**。

1. **可安装的 Cordis bundle**（遵循 harness 原生插件规范，即 `cordis-plugin-development` 特化 skill）：
   - `package.json` 声明 `dsh.bundle.patch` → `./cordis.patch.yml`；`cordis.patch.yml` 用 `insert:` 加一行插件 row（唯一 id/name）。
   - Host 插件入口二选一、**不混用**：`export function apply(ctx, config)`（可选 `export const inject` / `export const Config`），或 default export 的 service class；资源用 `ctx.effect` / `ctx.on` 注册并返回清理。
   - 全部文件落在本 workspace；**不手写 profile 的 `package.json` / `cordis.patch.yml`，不在 profile 目录跑 pnpm**——安装只走 `plugin_manager action: install_bundle`（`target` = 本 workspace 根的绝对路径）。
2. **工具链**：TypeScript（`tsconfig.json`）+ 单测运行器（推荐 vitest，与 DSH 主仓一致，`pnpm test` 一条命令）+ 构建产物（`lib/` 或 `dist/`，供 `install_bundle` 安装）。
3. **最小可观测注册**：暴露一个空壳 `agents` 服务（或等价空注册点）以便 01 继续填充，并能被 `cordis_inspect_query` 读到（Service / Event / Tool 任一），证明通路活着。
4. **目录约定**：`src/`（TS 源码）、`test/`（单测）、`bundled/`（内置资产落点，供 01 的内置「默认」agent 使用）。
5. **可回退**：`plugin_manager action: remove_bundle` 能干净移除；不以重启为准，以返回值 `application` 字段与 inspect 结果为准。
