# 09 — R2：别名内部负载控制与故障转移语义（研究）

Status: ready-for-agent
Type: research
Blocked by: —

## 问题

别名池内的选择与转移语义如何定义（spec §9-R2）。**约束已由用户定死：负载通常不均衡（主备不轮询）、只做故障转移、429 也不一定转移。**

## 开放问题

1. **故障分类学**：哪些错误触发转移（5xx / timeout / 401 / 网络错误）？429 为什么默认不转移（可能是瞬时限流，转移反而破坏缓存与人设调优）？
2. **与 llm-retry 的叠加语义**（核心问题）：DSH 已有同请求退避重试（默认 5 次：EMPTY_RESPONSE/RATE_LIMIT/SERVER/TIMEOUT/TRANSPORT，`llm/src/retry-policy.ts`）。我们的转移发生在**解析/preflight 层**（选好目标再交 DSH 执行）——两层如何组合？转移阈值（连续 N 次失败）还是错误类别优先？
3. **429 策略**：原地退避（吃 llm-retry）优先于转移？触发转移的条件是什么（限流持续 X 秒/连续 N 次 429）？
4. **恢复探测**：v1 = UI 手动 `available` 开关；v2 = 半开探测？谁探测（主会话试探 vs 子代理代价）？
5. **池序语义**：主备不轮询 ⇒ 池是有序数组，转移 = 向后走，恢复 = 回到队首？已转移会话中途要不要迁回？
